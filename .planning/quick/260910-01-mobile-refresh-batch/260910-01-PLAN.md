# Plan 260910-01: Mobile refresh affordances

## Context

`useTodaySong` uses `staleTime: Infinity` + MMKV PersistQueryClientProvider means the
cached today-song response survives force-quit. The only queryKey change that would
trigger a refetch is the `localCalendarDay()` daily rotation. When server-side state
changes mid-day (quota reset, reroll marker inserted, breakdown regenerated) the
client has no way to see the new state until either the day boundary or app reinstall.

Surfaced during device testing 2026-09-10: user hit quota cap; DB manipulation
reset the counters server-side, but the client kept showing `remaining=0` from the
persisted cache. User proposed a dev "reset button".

## Objective

Ship two refresh affordances so this cache-vs-server mismatch has a client-side
resolution path:

1. **Pull-to-refresh on the Today tab** — standard iOS/Android gesture,
   user-facing, invalidates today-song queries.
2. **Dev "Refresh cache" button in Settings** — explicit affordance for POC
   testing; invalidates ALL cached queries.

Bundle with the E♭ standard KNOWN_TUNINGS entry that already committed at
`ffdf2e7` but hasn't shipped as an EAS build yet — one EAS batch carries all
three changes.

## Tasks

### Task 1 — Pull-to-refresh on Today tab (`mobile/src/app/(tabs)/index.tsx`)

- Add `useCallback`, `useState` from React.
- Add `RefreshControl` from `react-native`.
- Add `useQueryClient` from `@tanstack/react-query`.
- Local `refreshing: boolean` state; `onRefresh` callback awaits
  `qc.invalidateQueries({ queryKey: ['today-song'] })` (broad predicate,
  catches every user/day tuple).
- Wire `refreshControl={<RefreshControl refreshing={refreshing} onRefresh={onRefresh} tintColor="#E07B39" colors={['#E07B39']} />}`
  on the ScrollView.

### Task 2 — Dev refresh cache button in Settings (`mobile/src/app/(tabs)/settings.tsx`)

- Add `useQueryClient` from `@tanstack/react-query`.
- New `onRefreshCache` handler → Alert with Cancel + Refresh confirm →
  `qc.invalidateQueries()` (no filter, wipes all query cache).
- Render a new "Dev" section label + outlined-button below the existing
  "Re-run onboarding" primary button. Muted styling (#444 border, #A0A0A0 text)
  to visually mark it as dev-tool, not user-facing.
