# Song catalog: 10 → 64

Paperclip issue **FLE-6 Task 8 — Expand the song catalog from 10 to ~60**.

Ten songs is one player's taste, and the session engine burns through material faster than
one-song-a-day did. This expands `song_catalog` to 64 entries, adds the `tuning` column the
tagging contract needs, and replaces "trust me, it's varied" with the tables in §2–§3 —
all of which are generated from the database, not asserted.

drills-bank tables, but 0006 must land on `main` before or with 0007 or `alembic upgrade
head` breaks on a missing `down_revision`.

## 2. Difficulty spread

`difficulty` is the selector's axis, not a vibe: `selectors/today_song.py` matches
`ABS(difficulty - player_level) <= 0.15`, where `player_level = AVG(mastery)` over the
user's leaf skill nodes. So the number means *"the leaf-mastery level at which this song is
the right stretch"*, not *"how impressive it sounds"*.

| Band | Songs | of which non-standard tuning |
|---|---:|---:|
| 0.15–0.29 beginner | 9 | 0 |
| 0.30–0.44 adv. beginner | 14 | 3 |
| 0.45–0.59 intermediate | 15 | 5 |
| 0.60–0.74 upper-intermediate | 14 | 8 |
| 0.75–0.89 advanced | 8 | 5 |
| 0.90–1.00 expert | 4 | 1 |
| **Total** | **64** | **22** |

**Selector coverage is the property that actually matters**, and it is asserted rather than
eyeballed: `test_no_empty_selector_window` sweeps `player_level` from 0.00 to 1.00 at 0.05
resolution and fails if *any* value has zero candidates within ±0.15 — that case is a real
user getting **no song at all** on a bank draw. `test_selector_window_density_at_anchors`
additionally requires ≥3 candidates at 0.20 / 0.50 / 0.80, since one candidate means every
bank draw at that level returns the same song and the reroll is cosmetic.

Zero non-standard tunings in the beginner band is deliberate, not an oversight: asking
someone at mastery 0.2 to retune before they can play the first thing they're handed is a
way to lose them on day one.

## 4. Licensing flags for v3 (Task 11)

Every composition in the catalog is under copyright **except** *Canon in D* (Pachelbel,
d. 1706) and *Recuerdos de la Alhambra* (Tárrega, d. 1909), both firmly public domain.
*Sweet Home Chicago* is often assumed PD and is not — Robert Johnson's 1937 publication does
not enter the US public domain until 2033.

The risk is not the catalog row itself — title and artist are facts. The exposure is v3
**distributing generated tab**, which is a derivative of the underlying composition. Ranked
by how likely the rights-holder is to act:

**Tier 1 — documented history of enforcement against tab/lyric sites.** Clear these first or
plan to drop them.

| Song(s) | Why flagged |
|---|---|
| *Blackbird* | Beatles catalog (Sony/ATV lineage) — among the most actively enforced song catalogs in existence. |
| *Little Wing*, *Purple Haze*, *Hey Joe*, *Voodoo Child (Slight Return)* | Experience Hendrix LLC is an unusually litigious rights-holder across both copyright and trademark. 4 entries. |
| *Hotel California* | The Eagles have a long record of pursuing unauthorized uses of this specific title. |
| *Kashmir*, *Black Mountain Side* | Led Zeppelin, Warner/Chappell. *Black Mountain Side* additionally has a disputed-arrangement history (Bert Jansch / "Down by Blackwaterside"), so provenance is contested on top of ownership. |
| *Nothing Else Matters* | Metallica's enforcement posture is a matter of public record. |

**Tier 2 — ownership is itself contested, so "who do we even license from" is the problem.**

| Song | Why flagged |
|---|---|
| *Hey Joe* | Authorship disputed (Billy Roberts vs. Dino Valenti). Also Tier 1 — this one is flagged twice. |
| *The Girl from Ipanema* | Subject of a copyright-reversion dispute among the Jobim/Moraes heirs; the correct counterparty is not stable. |
| *Wagon Wheel* | Dylan/Secor split authorship on a sketch completed decades after the original. |

**Tier 3 — standard commercial-catalog risk**, no special history: everything else. Normal
mechanical/print licensing assumptions apply.

**No song was excluded on licensing grounds here.** These flags are input to the Task 11
decision, not a substitute for it — dropping material now, before anyone has priced the
licence, would shrink the catalog for a cost nobody has measured.

## 5. Pre-existing bug found and fixed

`models/db.py`'s `SongCatalog` has declared `breakdown: Mapped[Optional[dict]]` since Phase 3,
but migration 0003's `CREATE TABLE` never added the column and no later migration did either.
Any ORM read of `SongCatalog` therefore raised `UndefinedColumnError: column
song_catalog.breakdown does not exist`. It never surfaced in the request path because
`selectors/today_song.py` queries `song_catalog` through raw SQL with an explicit column list,
never the ORM — but `tests/test_alembic_0003.py::test_song_catalog_orm_dual_default` has been
failing on it. Migration 0007 step 0 adds the column, which matches the already-declared
intent and is the reversible direction. That test is now green.

### 6b. What the sweep does not say — see FLE-49

`test_no_empty_selector_window`'s floor is *one* candidate, and `player_level = 0.00` has
exactly one (`Knockin' on Heaven's Door`, 0.15; the next entry is 0.18, outside the ±0.15
window). Checking who actually sits at that level: **all 16 production users do.** 3 of 250
leaf `skill_nodes` have non-zero mastery and the maximum anywhere is 0.050.

So in production today every seed-catalog bank draw returns the same song, reroll included,
and 63 of the 64 rows are unreachable by every account that exists.

The root cause is upstream of this task. `selectors/today_song.py:109` reads
`COALESCE(AVG(mastery), 0.5)` — written to give unknown players a mid-catalog level, but it
only fires when `AVG` returns `NULL`, i.e. when a user has no leaf nodes at all. Onboarding
creates the nodes and seeds them at `mastery = 0`, so `AVG` returns `0.0` and the fallback has
never once executed for a real user.

§3's density test is also implicated: it requires ≥3 candidates at 0.20 / 0.50 / 0.80 only,
and 0.00 is not an anchor. It asserts a floor of 1 at the exact level 100% of the user base
occupies. Tracked with the measurements and the recommended fix in **FLE-49**; the
pedagogy call recorded there is that mastery 0 is a *knowledge* state ("never observed") and
the selector currently reads it as a *skill* state ("can play nothing"). Adding catalog rows
below 0.15 is explicitly rejected as a fix — `Knockin' on Heaven's Door` is four open chords
and there is no honest tier of real songs beneath it.

## 7. Follow-up

`tuning` is **not yet plumbed into the Sonnet breakdown prompt.** Sonnet still infers tuning
on its own from the song title, which is precisely the path that produced the *Lenny*
incident. The column is curator ground truth today; propagating it through
`_ensure_catalog_song_as_user_song` → `songs` → the breakdown prompt (and asserting emitted
`tab.tuning` against it) is a separate, larger change and is filed as its own issue.
