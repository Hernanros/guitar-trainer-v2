## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MMKV local storage → app state | Cached query data is deserialized from MMKV on startup; no user-controlled input in the deserialization path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | MMKV cache contents on rooted device | accept | Phase 1 caches only the public song payload (no PII, no credentials, no user-specific data). On a rooted device, an attacker could read the MMKV database file; acceptable risk given the data is public. Phase 2 will evaluate if skill graph data warrants encryption. |
| T-03-02 | Tampering | MMKV cache poisoning on rooted device | accept | An attacker with root access could modify the MMKV cache. Phase 1 has no sensitive state. TanStack Query will overwrite the cache on next successful network response. |
| T-03-03 | Denial of Service | MMKV cache corruption causing crash on startup | mitigate | PersistQueryClientProvider handles deserialization errors gracefully — if cache is corrupt, it falls back to a fresh QueryClient state and refetches. This is the library's default behavior; no custom error handling needed. |
  | T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed in this plan. All MMKV and TanStack persistence packages were installed and audited in Plan 01. |
</threat_model>
