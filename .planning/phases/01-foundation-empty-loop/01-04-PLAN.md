<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mobile app → Railway HTTPS endpoint | App fetches from public Railway URL over HTTPS; Railway provides TLS automatically |
| EAS build → App bundle | EXPO_PUBLIC_API_URL is baked into the bundle at build time; it is a public URL — not a secret |
| Developer machine → EAS CLI | EAS CLI uses Expo account credentials stored locally; not in scope for this threat model |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | Railway service URL public exposure | accept | The Railway *.up.railway.app URL serves only public song data. No PII, no auth tokens. Public by design. |
| T-04-02 | Information Disclosure | EXPO_PUBLIC_API_URL in app bundle | accept | The public prefix (EXPO_PUBLIC_) signals this is intentionally client-visible. The URL points to a public GET endpoint. No secret leakage. |
| T-04-03 | Tampering | Railway auto-deploy from main branch | accept | Only Hernan has push access to this private repo. Auto-deploy from main is the intended workflow. Phase 4 adds Railway deploy hooks for production hardening. |
| T-04-04 | Spoofing | EAS internal distribution IPA/APK install | accept | Ad hoc IPA requires UDID pre-registration (only Hernan's device). Android APK requires manual install (sideloading). Neither is accessible to arbitrary users. |
| T-04-05 | Elevation of Privilege | Railway service without auth | accept | No sensitive data served. No write endpoints. Single-user POC. Phase 2 adds user identity when personal data lands. |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed in this plan. EAS build uses the mobile/package.json lockfile from Plan 01 (all packages already audited). |
</threat_model>
