## Critical Anti-Patterns (discovered through failure this session)

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Mock-at-decorated-boundary | `test_users_bootstrap_mocked.py` mocks `run_onboarding_parse` (the @governed-decorated fn) — this bypasses the decorator entirely. 4 of today's 5 P0s slipped past CI because tests mocked at this wrong seam. | blocking | Before ANY @governed-related change, verify tests exist that mock at `get_client` (network boundary) — NOT at the decorated function. If not, add one before writing more @governed code. |
| Server-side schema change without mobile co-evolution | 33d78ac loosened SongResponse.breakdown to Optional/None; current EAS build accessed it unconditionally → app crash. Whiplash cost 6ae712a coerce-to-empty bandaid. | blocking | Any SongResponse or top-level API schema change MUST verify the current in-field EAS build handles the new shape, OR ship a co-evolved mobile build in the same cycle. If EAS quota constraints prevent co-evolution, use server-side coerce-to-safe-shape as a bridge and capture the mobile guard as a follow-up. |
| @governed inside SAVEPOINT with shared session | @governed's `_insert_governor_call` calls `db.commit()` which closes any enclosing SAVEPOINT. Passing the outer session (inside `db.begin_nested()`) → SAVEPOINT dies mid-flight. | blocking | Any @governed call site nested inside `db.begin_nested()` MUST pass a fresh `AsyncSessionLocal()` for the governor bookkeeping. See `_bounded_verify` (users.py:210) and `_run_onboarding_parse_bounded` (added in def6ba8) for the correct pattern. Memory: `feedback_governed_savepoint_pattern`. |
| Sonnet output allows duplicates DB constraint forbids | Sonnet can emit multiple SongProposal entries with same (title, artist) if user mentioned song in multiple wizard categories. DB unique index is (user_id, lower(title), lower(artist)) — no category. Insert loop crashes on second flush. | advisory | Coalesce (title, artist) pairs before insert with a defined category precedence. Also tighten Sonnet prompt to dedupe. See `_coalesce_song_proposals` in users.py. |
| Cascade drop for verifier-dropped subs | Verifier drops a sub-level node but its leaf children still insert with orphan parent_id → FK violation at commit (DEFERRABLE FK). | advisory | Any pipeline that can drop parents in a tree must cascade the drop to children before insert. See cascade-drop pass in `_persist_bootstrap` (users.py, added 115fc05). |

**Do not proceed with new work until these are understood.**
