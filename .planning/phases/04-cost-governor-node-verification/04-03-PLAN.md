<objective>
Slice C — Skill-node verification pipeline end-to-end.

Ship the dedup + Sonnet verifier + curator queue flow that intercepts onboarding-Sonnet-emitted skill_node proposals BEFORE they land in the canonical graph (SKILL-04). Confident proposals join the graph, uncertain ones queue for curator review at `/api/v1/admin/curator`, and Sonnet-rejected ones drop with an audit row.

**Working end-to-end at completion:** a fresh user goes through onboarding with a novel skill name like "Odd-Time Metric Modulation"; server-side, run_onboarding_parse emits this as a proposed node → dedupe_score returns < 70 against existing canonical names → run_skill_node_verify (Sonnet) returns a verdict → the node either joins the graph (verdict='yes' with root assignment), gets queued at /admin/curator (verdict='uncertain'), or drops silently (verdict='no' with skill_node_rejections row). Governor logs each verifier call in governor_calls.

Purpose: prevent Sonnet from silently proliferating near-duplicate skill names in the graph, satisfy SKILL-04's "confident → canonical, uncertain → curator queue" contract, and prove the governor decorator plumbing works for a second call site (skill_verify).

Output: skill_dedupe.py + skill_verifier.py + onboarding hook + admin router (2 endpoints) + get_admin_token dep + SkillNodeVerifyOutput Pydantic model + 4 test files covering dedupe/verifier/pipeline/admin.
</objective>

Verifier pipeline hook contract (inside run_onboarding_parse, D-13):
For each `SonnetSkillNodeProposal` in the parsed output where level in ('sub','leaf'):
  candidate_names = [existing canonical name for canonical nodes matching same level+root]
  match = best_match(proposal.name, candidate_names)
  if match and match.score >= SCORE_AUTO_DEDUPE:
      -> reuse existing canonical (set canonical_node_id = existing_canonical.id on the new user-scoped row)
  elif match and match.score >= SCORE_CURATOR_QUEUE:
      -> insert skill_node_proposals row (status='pending', fuzzy_score=match.score) and STILL insert the user-scoped skill_node row (canonical_node_id=NULL) so onboarding graph is complete for this user
  else (score < 70 or no candidates):
      -> await run_skill_node_verify → verdict routes:
          'yes' -> insert node as new canonical (canonical_node_id=self.id)
          'no' -> DROP node (do not insert into skill_nodes) + insert skill_node_rejections row
          'uncertain' -> insert skill_node_proposals row (status='pending') AND insert user-scoped skill_node (canonical_node_id=NULL)
Roots (level='root') are NEVER verified — the 6 fixed roots are hardcoded per Phase 2 D-08.
