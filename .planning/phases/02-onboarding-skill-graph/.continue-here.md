## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| RESEARCH.md staleness on cloud infra | Wave 1's RESEARCH.md documented Railway as using Nixpacks + injecting `postgres://`. Reality (as of 2026-07-19): Railway defaults to Railpack (not Nixpacks) and injects `postgresql://`. Wave 1's session.py scheme rewrite only handled the legacy form → uvicorn crashed on import at Wave 3 deploy. Cost us one debug loop; caught quickly because Alembic ran cleanly (which showed the DB WAS reachable — the issue was downstream in the async engine). | advisory | Before executing any phase that depends on cloud-infra research (Railway, EAS, Anthropic API surface), do a smoke-check of the top 2–3 documented pitfalls against current provider behavior. Doesn't need to be exhaustive — just "has this changed since the research was written?" For Phase 2 specifically, this means: verify the Sonnet API surface hasn't shifted before wiring the batch parse call. |
| Design brief overshoot when translating cultural references | First draft of `fletcher-identity.md` translated the JK Simmons character too literally into product voice — "sparing praise, no emojis, direct, cold". User course-corrected: "the app isn't designed to make you feel bad" — grinders need reinforcement, not real-Fletcher's cruelty. Fixed in 2 rounds (sanitized too much → user asked for vocabulary back → landed on "diagnosis + coaching + confidence signal" pattern). | advisory | When drafting design briefs based on cultural characters, first write the product's actual intent, THEN check if the reference serves that intent. Not the reverse. The joke should serve the product, not vice versa. |
