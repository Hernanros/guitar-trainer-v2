## Deviations from Plan

### Rule 1 — Bug fix: cached-JSONB round-trip failure

**Found during:** Task 2 (test_cache_hit_skips_sonnet regressed)

**Issue:** Pydantic v2's `model_dump()` on a Breakdown WITHOUT explicit drills still includes `"drills": []` in the output dict (defaults get serialized). On cache-read the endpoint called `Breakdown.model_validate(song.breakdown)` — and Pydantic treats an explicit `drills: []` as EXPLICIT INPUT, triggering `min_length=2` → 500. This would break every cache-hit read of drill-less breakdowns (both pre-4.1 rows written before this plan AND post-4.1 rows where Sonnet legitimately produced no drills after a Landmine #3 soft-fail).

The plan's must_have truth #1 asserted "the default satisfies backward compat for pre-4.1 cached breakdowns because model_validate short-circuits list-length checks for a default-produced empty list — verified in Task 1 tests." That claim is TRUE only when the `drills` KEY is absent from the input dict. When the key is present-with-empty-list, min_length fires.

**Fix:** Added `_load_cached_breakdown(cached: dict) → Breakdown` helper in server/app/api/v1/breakdowns.py that pops the `drills` key from the input dict if it's an empty list before calling `Breakdown.model_validate`. Real drill lists (2-4 items) pass through unchanged. Both cache branches (cache-hit read + persistence read-back after Landmine #3 soft-fail) go through this helper.

**Files modified:** server/app/api/v1/breakdowns.py

**Commit:** 16e7c83

### Rule 2 — SYSTEM_PROMPT copy adjustment to match verbatim substring assertions

**Found during:** Task 2 test run

**Issue:** RESEARCH.md §Q1 "Recommended prompt additions" (which the plan quoted as verbatim) used the phrasing:
- `DO NOT copy a slice of the main song tab.`
- `` `song_specific: true` if `` (with backticks)

But the plan's must_have truth #3 required the SYSTEM_PROMPT to contain literal substrings:
- `MUST NOT be a slice of the main song tab`
- `song_specific: true if` (no backticks)

**Fix:** Adjusted the DRILLS block copy in SYSTEM_PROMPT to satisfy both — replaced "DO NOT copy" with "It MUST NOT be" (semantically identical; the negative-example intent is preserved), and dropped the backticks around `true`/`false` in the song_specific tagging paragraph. Substance unchanged; only formatting to match the plan's explicit verify assertions.

**Files modified:** server/app/ai/breakdown.py

**Commit:** 16e7c83
