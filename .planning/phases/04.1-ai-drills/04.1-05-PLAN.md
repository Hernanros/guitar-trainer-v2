Prove that the drill-emission mechanism from Plan 01 actually produces GOOD drills at ship-quality. CONTEXT.md + RESEARCH.md both flag Sonnet output fidelity as the single largest risk (same class as Task #16 tuning quality). Automated schema tests can't catch "Sonnet lazily sliced the main tab into tab_snippet" or "song_specific tagging is wrong" — a human eye on 5 songs' worth of real drill JSON is the only defense.

**Working end-to-end at completion:** A live-Anthropic script generates drills for 5 tuning-diverse songs, prints them in a reviewer-friendly format, and the user fills in a landmine gate table (30 gates: 5 songs × 6 landmines from RESEARCH.md). **N1 CAVEAT** — the eval script uses FAKE target_skill_temp_ids (uuid4() generated ad-hoc, not backed by real skill_nodes rows), so L2 (hallucinated id) coverage in the eval is limited: the eval will always show `target_skill_temp_id` as "in the provided list" if Sonnet echoes any valid uuid from EVAL_SONGS. Real L2 coverage (Sonnet hallucinating an id NOT in the provided list) requires a real user's breakdown after Wave 3 lands. Task 3 device verification step o (query user_sessions after a real drill rating on a real user) provides that coverage.

Output: eval script (with W5 fix — no SQLite fallback, real dev-DB required), skip-by-default pytest wrapper, filled-in eval results doc, and two user checkpoints (one for eval sign-off, one for device sign-off). This plan is NOT autonomous — it has two blocking human-verify checkpoints.
