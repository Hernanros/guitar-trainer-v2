<objective>
Slice 2 — Server-side per-drill rating write path AND server-derived drill-state envelope (B1 fix).

Extend the existing POST /api/v1/sessions handler so it accepts optional `drill_index` + `target_skill_node_id`, writes mastery ONLY to that skill_node (not the whole song's leaf set), and enforces the "drill-primary, hard block on song rating" aggregation policy per RESEARCH.md §Q3 Option A (which overrides CONTEXT.md's tentative scaled-down default per orchestrator constraints).

**B1 FIX (server-derived drill state):** Wrap GET /api/v1/songs/{id}/breakdown's response in a `BreakdownEnvelope` that additionally carries `drill_rated_today_indices: list[int]` — computed on every request from user_sessions. This becomes the durable source of truth for the mobile drill-primary UI state, replacing the fragile QueryClient mutation-cache subscription pattern flagged by the checker. The Breakdown itself (cached JSONB per D-11) is NOT modified — the envelope wraps it.

**Working end-to-end at completion:** A pytest that POSTs a drill rating (drill_index=0 + target_skill_node_id=<uuid>) writes to exactly one SkillNode row. A follow-up POST for a song-level rating (drill_index=NULL) for the same song+day returns 409 with `{code: "SONG_RATING_BLOCKED_BY_DRILL"}`. A concurrent double-tap on the same drill_index returns 409 via the recreated partial-unique index. GET /api/v1/songs/{id}/breakdown after a drill rating returns `drill_rated_today_indices: [0]` in the envelope; before any drill rating, it returns `[]`.

Purpose: this is the write half of DRILL-03 + the state-envelope for B1. Plan 04 (mobile drill-detail screen) consumes both the sessions endpoint AND the drill_rated_today_indices field. Landing it in Wave 2 (right after the Drill schema in Plan 01) means the mobile plans can be built against a live, tested contract — not a placeholder.
