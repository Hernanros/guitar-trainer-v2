## Parallel-Execution Race (Wave 2)

**What happened:**

Wave 2 ran Plans 03 (this one, mobile-only) and 02 (server-only) as parallel executors against the same working tree. The plans have zero files_modified overlap by design — but git operations do NOT respect the plan's file-scope invariant.

Sequence:
1. My Tasks 1 + 2 committed cleanly (450be50, 5b05394).
2. I made Task 3 mobile edits (unstaged).
3. Plan 02 finished its Task 1 and ran `git add server/alembic/... server/tests/...` — but because my mobile files were unstaged-modified in the tree AT THAT MOMENT, they were ALSO caught up in Plan 02's implicit-scope collection when they staged. Plan 02's commit 922ef0b thus contained BOTH server AND my mobile files.
4. I detected 922ef0b bundled my files (confirmed via `git show 922ef0b -- mobile/`).
5. Plan 02's executor then ran `git reset HEAD~1` (visible in `git reflog HEAD@{1}`) which undid 922ef0b, putting all its content back into working-tree unstaged state.
6. I did `git commit --allow-empty` with a marker message thinking my files were already committed. But the reset had put everything back in staged state (or my earlier `git add` had staged mobile files that persisted through the reset), so my commit picked up ALL the changes since 5b05394 — both my mobile diff AND Plan 02's server files.
