## Two corrections to the wording proposed in 04.1-05

The eval doc proposed wording for all three fixes. Two of the three needed changing
before they were safe to ship. This is the pedagogy review, and it is the substantive
part of this document.

### C1 — the proposed difficulty formula is additive over incommensurable units

04.1-05 §"Required prompt changes" proposed:

> Difficulty = number of strings + number of distinct shapes + whether a chord change
> occurs + whether rhythm is displaced.

Summing these produces wrong orderings, because string count ranges 1–6 while the
other three terms are 0–1. String count dominates the sum outright:

| Drill | strings | shapes | change | displaced | **sum** | actually harder? |
|---|---|---|---|---|---|---|
| Open G strummed, one shape, on the beat | 6 | 1 | 0 | 0 | **7** | no — this is a beginner drill |
| Two-string syncopated chromatic run | 2 | 1 | 0 | 1 | **4** | **yes** |

The formula ranks the six-string beginner strum as nearly twice as hard as the
syncopated run. If we ship it, we have replaced "no definition of difficulty" with
"a definition that is confidently wrong" — which is worse, because the model will
now follow it consistently.

**Replaced with a dominance rule over five named dimensions.** No arithmetic across
units: each drill is rated per dimension, and reading the drills in order, no
dimension may decrease and at least one must increase. That is mechanical, checkable
in one pass, and never asks the model to decide whether a string is worth a
syncopation.

### C2 — the tempo contradiction has a correct answer, and it is not monotonic BPM

04.1-05 left this open ("either require `start_bpm`/`target_bpm` to be non-decreasing
across drills, or state that tempo is not the difficulty signal"). It has to be
resolved in the prompt text, so I am resolving it:

**Tempo is not the difficulty signal. Drop it.**

A harder mechanic is usually drilled *slower*, not faster. A 16th-note run is
practised at 50 BPM; a whole-note chord change is practised at 80. Requiring
non-decreasing BPM across drills would force the hardest drill to carry the highest
tempo — the opposite of how anyone practises, and it would degrade the drills we
already grade as correct. `Drill._target_bpm_above_start` already enforces the only
BPM relation that matters, and it is *within* a drill, not across drills. There is
no cross-drill BPM constraint anywhere in the schema, and there should not be one.

**This changes a gate definition, and it is being changed with results in hand.**
The L5 "by tempo, 5/5 fail" reading in 04.1-05 is retired — not because the output
passed it, but because the criterion was wrong pedagogy. Flagging it explicitly
because 04.1-05 states the 30 gates were fixed *before* any live output existed,
and I am the one breaking that property. The re-grade must record L5 as
complexity-ordering only. If whoever grades the re-run disagrees, the disagreement
should land before the run, not after. The complexity reading of L5 (3/5 FAIL) is
unchanged and still the thing being fixed.

### Accepted as proposed

**L4** needed no change — it was already stated mechanically. I kept its two
directions and added only the instruction to actually perform the scan.

## The replacement text

Replace `breakdown.py` lines 104–131 in full (from `DRILLS (produce 2-4):` through
`...skip that drill rather than mislabel it.`) with:

```text
DRILLS (produce 2-4):
After the main tab/chords/technique_notes, emit 2-4 short practice drills.
Each drill isolates ONE skill from the target_skills list and must be
playable in under 60 seconds per rep.

SONG_SPECIFIC — this is a mechanical test, not a judgement call:
If the drill's `what` text contains the song title or the artist name
anywhere, then `song_specific` MUST be true. There is no exception, and it
does not matter how incidental the mention is. If you intend a foundational
drill that any guitarist could use regardless of song, then do not mention
the song title or the artist in `what` at all — rewrite the copy to describe
the mechanic only. Scan `what` for both strings before you emit.

For `tab_snippet`: compose a CANONICAL EXERCISE SHAPE that isolates the
technique. It MUST NOT be a slice of the main song tab. The snippet should
be 1-2 measures maximum and exercise ONE mechanic per drill.

SELF-CHECK, run this on every drill before emitting it:
Compare the snippet against every measure of the main tab you just wrote.
Compare ONLY the ordered sequence of (string, fret) pairs — ignore the time
signature, ignore note durations, and ignore notes added or removed at
either end. If 3 or more consecutive (string, fret) pairs appear in the same
order in any main-tab measure, the snippet is a slice: rewrite it.
Relabelling the time signature, appending a note, or shifting by an octave
does NOT stop it being a slice.

BAD: `tab_snippet` is measures 3-4 from the main song tab.
BAD: main tab measure is [6/7] [5/9] [4/9] [3/8] [2/8] in 12/8, and the
     snippet is [6/7] [5/9] [4/9] [3/8] [2/8] [3/8] relabelled 4/4. Five
     pairs match in order. This is a slice wearing a disguise.
GOOD (single-note mechanic): `tab_snippet` is just the two-note slide on
     one string, played alone, no bass, no chord — isolated so the user
     drills the mechanic not the song.
GOOD (chord or barre mechanic): reduce the shape, never quote the song.
     Play only the two or three strings that carry the mechanic, or hold
     the full shape and drill the attack alone on a rhythm you invented.
     For an E-shape barre at position VII: [6/7] [5/9], then
     [6/7] [5/9] [4/9], then the full shape struck on each beat. Do not
     reproduce the song measure that contains that chord.

DRILL ORDER — easiest to hardest, defined so you can check it:
Rate every drill on these five dimensions, reading its own tab_snippet:
  (a) number of distinct fretted shapes
  (b) whether changing between shapes is required (no / yes)
  (c) the most strings sounded together in any one beat (1-6)
  (d) whether the fretting hand must shift position (no / yes)
  (e) whether the rhythm is even or displaced/syncopated (even / displaced)

Drill 1 MUST be the simplest mechanic you emit: one shape, no change, no
shift, even rhythm. Then, reading the drills in order, no dimension may go
DOWN from one drill to the next, and at least one dimension MUST go UP. If
your drills cannot be ordered that way, change the drills — simplify an
early one, or emit fewer — rather than emitting them out of order.
As a specific case of that rule: a drill that is one static shape must
NEVER appear after a drill containing a chord change.

TEMPO IS NOT THE DIFFICULTY SIGNAL. Do not try to make start_bpm or
target_bpm rise across drills. A harder mechanic is often drilled SLOWER
than an easy one, and that is correct. Set each drill's tempo from its own
note density alone: start_bpm is a comfortable warmup for that specific
mechanic, target_bpm is a stretch 10-40 BPM higher, both in 5-BPM
increments to match the skill graph's 5-bpm bins. Repetitions: 8-30 per
tempo step.

target_skill_temp_id MUST be one of the ids listed in the user message.
Do not invent ids. If none of the listed skills fit a drill you'd
naturally emit, skip that drill rather than mislabel it.
```

### Change map

| Gate | Was | Now | Mechanism added |
|---|---|---|---|
| L4 `song_specific` | "tag true if the copy references THIS song" (semantic) | title-or-artist substring test on `what`, both directions | a scan the model can actually run |
| L1 isolation | one BAD, one GOOD (single-string only) | + 3-consecutive-pair self-check, + disguise clause, + second BAD reproducing the real Lenny failure, + GOOD for chord/barre | a comparison, and a worked example for the drill type that failed |
| L5 ordering | "Order drills easiest→hardest" | 5 dimensions + dominance rule + static-after-change ban + explicit tempo carve-out | a definition and a check |

Each of the three failures came from the prompt stating a goal with no mechanism to
verify it. Every edit above adds the missing mechanism, and adds nothing else.

## OPTIONAL 4th change — not part of FLE-17 §2, decide separately

04.1-05 logged as lower-severity: *Little Wing D3 drills an open-position Em at frets
0–2 while the main tab puts that passage at frets 7–10 in E♭.* It passed L1 (genuinely
not a slice) but teaches a shape the song does not use — which is a real pedagogy
defect even though no gate caught it.

One paragraph fixes it, appended to the DRILL ORDER block:

```text
A drill must use the same tuning and the same region of the neck as the
main tab passage it prepares. If the main tab places that passage at frets
7-10, do not build its drill on an open-position shape — the user would be
practising a shape the song never uses. Open position is correct only when
the main tab is in open position.
```

**Recommendation: include it in the same re-run.** It costs nothing extra (same 5
calls, same spend) and testing it separately means paying for a second run. Not
folding it into the required three silently — it needs a yes, and it is not mine
to decide alone since it widens the agreed scope of FLE-17 §2.

If it goes in, add a 31st gate: *every drill's fret region overlaps the main-tab
region for the passage it prepares.* Little Wing is the known-failing case.
