## 1. L5 — the dominance rule is wrong, and it is my wording

All four gradeable songs fail it. But only two of the four failures are the model's:

| Song | Violation | Real? |
|---|---|---|
| Kashmir | D2→D3 drops shapes, change **and** position shift; D3→D4 nothing rises | **yes** — D3 and D4 are genuinely easier than D2 |
| Lenny | D1→D2 drops shape count; D3→D4 drops rhythmic displacement | **yes** — D4 is a single-string chromatic walk placed last |
| Little Wing | D3→D4 drops `c_voices` (2 → 1) | **no** — D4 is a 6-note bass-chord-melody roll, clearly the hardest drill; it just sounds one string at a time |
| Beat It | D3→D4 drops `d_shift` | **no** — D4 trades a position shift for a cross-string root change, which is harder |

The rule I shipped says *no dimension may decrease and at least one must increase*. Little
Wing and Beat It show why that is too strong: **real difficulty progressions trade
dimensions.** Dropping to single notes while adding melodic independence is harder, not
easier. A rule that forbids every trade forbids most correct orderings.

I rejected the original additive formula for being confidently wrong. The dominance rule I
replaced it with is the opposite failure — defensible in every individual case and
unsatisfiable in aggregate. Both attempts share a root cause: **difficulty is not a
function of the snippet's geometry.** The next attempt should stop trying to compute it and
instead give the model an ordered tier list of named mechanics (single sustained note →
two-string alternation → held shape struck → shape change → shape change with position
shift → polyphonic independence), and require the drill sequence to be non-decreasing in
*tier*. One dimension, ordinal, checkable, and it does not forbid trades within a tier.

**Tempo stays retired** (approved: `retire-l5-tempo-gate`). This run supports the call
independently: the hardest drill carries the *lowest* start_bpm in 3 of 4 songs
(Lenny 45, Little Wing 45, Beat It 50), which is correct pedagogy and would have been
graded FAIL by the old non-decreasing-BPM reading.

## 2. L1 — the fix worked, and the wording has the same flaw as L5

Lenny, the run-2 failure, now passes: no drill reproduces the song. The added chord/barre
GOOD example did its job.

Kashmir fails, and it exposes a wording bug. The self-check I wrote says *"3 or more
consecutive **(string, fret) pairs**"*. Over a flattened note list, a single three-note
chord voicing is three consecutive pairs — so **any drill that reuses one of the song's
chords violates it**, which the neck-region rule now actively requires. As literally
written the two rules contradict each other.

`grade_eval.py` therefore compares **beats**, not notes: a chord is one beat, and a
violation is three consecutive *beats* of the song reproduced in order. Under that reading
Kashmir D1 and D4 still fail — D1 is the sus4 voicing struck on four quarter notes, which
is exactly main measure 2 — so the failure is real, not an artifact. But the prompt needs
the same correction, or it is asking for something impossible.

Kashmir also shows the limit of the gate: when the song's own passage *is* one chord struck
repeatedly, no isolation drill for that chord can avoid reproducing it. The rule needs an
explicit carve-out for a repeated single shape.

## 3. L7 (new, neck region) — passes 4/4, but it cannot catch the case that motivated it

Every snippet's fretted span overlaps a main-tab measure's span. Worth stating plainly
though: the gate compares the drill against **the tab we generated**, not against the
recording. The original complaint was that Little Wing's drills teach open position while
the *record* plays that passage at frets 7-10. In this run the model's Little Wing tab is
itself largely open-position, so drill and tab agree and L7 passes — while the underlying
fidelity question is untouched.

L7 is worth keeping; it just enforces internal consistency. **Tab-vs-recording fidelity is
a different, still-unmeasured problem** and needs a different instrument.

## 5. NEW — `song_specific` is still wrong, and the prompt cannot fix it

Kashmir D3 and D4 say *"the engine of the **Kashmir** groove"* and *"the core of the
**Kashmir** riff"*, both with `song_specific: false`. The rule they violate is about as
mechanical as English gets: *if `what` contains the song title or artist, `song_specific`
MUST be true.*

The model is not failing to follow an ambiguous instruction — it is overriding a clear one
with its own semantics, because these drills *are* generic mechanics that merely name the
song. Restating the rule more loudly will not help; it was already restated once and it
worked on Lenny and failed here.

**This belongs in code, not the prompt.** A Pydantic validator on `Drill` can set
`song_specific = True` when the title or artist appears in `what`, deterministically, at
zero cost. The prompt instruction can stay as a hint, but the guarantee should not depend
on it.

## Item 3 — the dominance rule is retired, not repaired

`mechanic_tier` (1-6) is now a field on `Drill`. The model declares which tier
its drill's hardest moment sits in, against an ordered list of named mechanics
in `SYSTEM_PROMPT`:

| Tier | Mechanic |
|---|---|
| 1 | single sustained note |
| 2 | two-string alternation |
| 3 | held shape struck |
| 4 | shape change |
| 5 | shape change with position shift |
| 6 | polyphonic independence |

Gate L5 checks one thing: the declared tiers are non-decreasing down the drill
list. Equal tiers are legal, which is what makes a *trade* expressible at all.

**Why declared and not computed.** The grader cannot derive the tier, and
neither could a smarter formula. Little Wing D4 is a six-note
bass-chord-melody roll — tier 6, the hardest drill in its set — and it is
emitted as sequential single notes, so every geometric measure reads it as
*easier* than the two-string drill before it. That is not a proxy that needs
tuning; it is the wrong kind of question. Difficulty is not a function of the
snippet's geometry, which is the root cause shared by 04.1-05's additive
formula and 04.1-06's dominance rule. So the model declares and the eval
grades the declaration.

The five dimensions are still computed and printed per drill. They gate
nothing now — they are how a reviewer spots a declared tier the geometry
flatly contradicts.

**Guard.** `server/tests/test_grade_eval_gates.py` replays all four songs'
real drill sequences. The bar was not "L5 passes more often":

- Little Wing D3(T3)→D4(T6) — PASSES, was a false failure
- Beat It D3(T4)→D4(T4) — PASSES as an equal-tier trade, was a false failure
- Kashmir D2(T4)→D3(T2) — still FAILS, genuine regression
- Lenny D1(T3)→D2(T1) — still FAILS, genuine regression
- a drill omitting `mechanic_tier` — FAILS, so cached-row compatibility cannot
  become a way for fresh output to skip the gate

## Item 3b — L1 wording now matches the grader and the neck-region rule

The self-check's comparison unit is the BEAT. A three-note chord voicing is one
beat, so reusing one of the song's chords is no longer a violation — three
consecutive *beats* of the song in order is. This removes the contradiction
with `524352e`, which requires drills to live in the song's own region.

Added the carve-out Kashmir implies: when the passage *is* one shape struck
repeatedly, no isolation drill for it can avoid reproducing it, so the prompt
now directs drilling the ATTACK on an invented rhythm rather than demanding the
impossible. **Kashmir D1/D4 still fail L1 under the corrected reading** — the
wording was wrong, the verdict was not.
