## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | Mobile app sends X-User-ID + X-Timezone-Offset; server MUST validate offset range and treat user_id as identity-only (no authorization gate — POC single-user) |
| API → Postgres | Selector CTE binds :user_id, :tz_offset_minutes, :local_calendar_day, :player_level as parameters; NO string interpolation |
| Postgres → API | `song_catalog` is world-readable (seed data, global); `user_sessions` is per-user (all reads/writes MUST filter by x_user_id) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Tampering | X-Timezone-Offset header | mitigate | `get_tz_offset_minutes` dep parses `int(x)`; range-check `[-840, +840]` (per RESEARCH §6, matches Postgres INTERVAL bounds); reject 400 outside range. No raw-string interpolation into SQL — `:tz` bind param only. Log offsets outside `[-720, +840]` (Baker Island to Line Islands) at WARN level for suspicious clients but do not block. |
| T-03-01-02 | Elevation of Privilege | POST /today-song/reroll | mitigate | Reroll insert filters `WHERE user_id = X-User-ID`; UNIQUE partial index `WHERE is_reroll_marker` prevents any second reroll insert for that (user_id, local_calendar_day). No cross-user reroll possible because song_id from reroll response is server-selected. |
| T-03-01-03 | Denial of Service | Repeated reroll requests | mitigate | DB partial-unique index on `(user_id, local_calendar_day) WHERE is_reroll_marker` — second concurrent INSERT raises IntegrityError → mapped to 409. No Sonnet call in this slice (breakdown is Slice B), so DoS surface is a SQL SELECT + INSERT round-trip per request, negligible. Application-level COUNT-before-insert short-circuits legibility for the common case. |
| T-03-01-04 | Information Disclosure | GET /song-of-day cross-user | mitigate | Selector CTE filters `WHERE s.user_id = :user_id` on the songs half; `song_catalog` half is intentionally public (seed data). Bank ∪ ordering + LIMIT 1 return one song_id which is then loaded via `SELECT song WHERE id = :song_id AND (user_id = :user_id OR song_catalog_id IS NOT NULL)` — see task 2 for the exact access-control check. |
| T-03-01-05 | Tampering | Client-computed local_calendar_day | mitigate | Server never trusts a client-sent calendar day. Server derives it via `DATE((now() AT TIME ZONE 'UTC') + (:tz * INTERVAL '1 minute'))` where `:tz` is the range-validated header. A malicious client that ships `tz=+840` can only shift itself into the "wrong" day by 14h, not fabricate rate-limit bypass, because the UNIQUE constraint uses server-computed day. |
| T-03-01-06 | Tampering | Deterministic seed collision | accept | `hashtext(:user_id::text \|\| '\|' \|\| :local_day::text)` — the `'\|'` delimiter (per RESEARCH §8 landmine 3) prevents concatenation-ambiguity collisions. Postgres `hashtext` is int4; birthday-collision at POC scale (single-user, 30 draws/month) is not a real threat. |
| T-03-01-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages this plan (verified: `anthropic`, SQLAlchemy, Alembic, @tanstack/react-query, react-native-svg, MMKV, Zustand all installed Phase 1/2). No slopcheck / legitimacy audit required. |

    export async function apiFetch<T>(path: string, init: RequestInit = {}): Promise<T> {
      const base = process.env.EXPO_PUBLIC_API_URL;
      if (!base) throw new Error('EXPO_PUBLIC_API_URL is not set — check your .env or eas.json env config.');
      const url = `${base}${path}`;
      const userId = getOrCreateUserId();
      // Date().getTimezoneOffset() returns minutes WEST of UTC (positive for negative offsets).
      // Negate so X-Timezone-Offset uses the ISO-8601 sign convention (UTC-5 → -300).
      const tzOffset = -new Date().getTimezoneOffset();
      const res = await fetch(url, {
        ...init,
        headers: {
          'Content-Type': 'application/json',
          'X-User-ID': userId,
          'X-Timezone-Offset': String(tzOffset),
          ...(init.headers ?? {}),
        },
      });
      if (!res.ok) throw new Error(`HTTP ${res.status} ${init.method ?? 'GET'} ${path}`);
      return res.json() as Promise<T>;
    }

    export type TodaySongResponse = components['schemas']['TodaySongResponse'];

    export function localCalendarDay(): string {
      const now = new Date();
      const offsetMs = now.getTimezoneOffset() * 60 * 1000;
      const localMidnight = new Date(now.getTime() - offsetMs);
      return localMidnight.toISOString().slice(0, 10);

    export function useTodaySong() {
      const userId = getOrCreateUserId();
      return useQuery({
        queryKey: ['today-song', userId, localCalendarDay()],
        queryFn: () => apiFetch<TodaySongResponse>('/api/v1/song-of-day'),
        staleTime: 1000 * 60 * 60 * 12,
        refetchOnWindowFocus: false,
