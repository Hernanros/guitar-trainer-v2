# Phase 3 — UI Design Contract

> Visual and interaction contract for the daily-loop UI: Today card, breakdown loading, breakdown detail, rating pills, error + empty states, and post-rating rest state. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Voice contract:** `.planning/design/fletcher-identity.md` governs every user-facing string. No emojis. No exclamation points. Every diagnosis carries a next step; every praise references what was earned.
>
> **Palette + primitives locked:** Phase 2 established the `#1A1A1A / #F5F5F5 / #E07B39` palette, the `themed-text` primitives, and the `FletcherIntroCard` / `RetentionFormatRadio` visual language. Phase 3 reuses everything; no new colors, no new fonts, no new SVG primitives.

Declared values (all multiples of 4, aligned with the 8pt grid Phase 2 established):

| Token | Value | Usage in Phase 3 |

| lg | 24px | Vertical gap between section blocks (technique notes → tab → chords → rating pills); breakdown card top padding |

**Exceptions (all justified):**

| Value | Where | Why |

## Typography

Font sizes are constrained to **4 tokens** (body, label, heading, display) plus 2 fixed micro-uses (eyebrow, meta) that already exist in Phase 1/2 code — deliberately narrow to keep the design language tight.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Body | 16px | 400 (regular) | 22px (1.375) | Fletcher line above song, technique-note body copy, empty-state body |
| Label | 14px | 600 (semibold) | 20px (1.43) | Rating pill labels, re-roll ghost button, technique-note heading, "From the bank" chip label |
| Heading | 20px | 700 (bold) | 24px (1.2) | Song title on `SongOfDayCard`, breakdown section headings ("Tab" / "Chords" / "How to play it") — but see note below |
| Display | 24px | 800 (extra-bold) | 28px (1.17) | Post-rating acknowledgement one-liner; onboarding-style heading if we ever hit the empty-graph state |

**Existing Phase 1 usage (do NOT change):**

| Role | Size | Weight | Where |
|------|------|--------|-------|
| Eyebrow | 11px | 700, letter-spacing 1.5px, uppercase | "TODAY'S SONG" eyebrow — retained from `index.tsx` for continuity |
| Meta | 13px | 400 | "Blues · 84 BPM · Key of E" secondary metadata line — retained |
| Section title | 12px | 700, letter-spacing 1, uppercase | "HOW TO PLAY IT" / "TAB" / "CHORDS" section eyebrows in the breakdown — retained from `index.tsx` |

**Rationale for narrow scale:** Phase 1 index.tsx already establishes 24px bold as the song title and 12px uppercase as section eyebrows. Phase 3 does NOT introduce a new heading size — the breakdown detail view keeps Phase 1's exact typographic rhythm. The new 20px heading token is reserved for the `SongOfDayCard` variant that shows *only* the song title (when the breakdown isn't yet loaded), because it needs to be visually dominant without the full breakdown supporting cast around it.

**Weight discipline:** exactly two weights carry the design — 400 (regular body) and 700 (bold headings/labels), with 800 reserved for the single song-title display. Semibold 600 appears only inside the rating-pill labels and technique-note headings, matching the existing `techniqueHeading` style in `index.tsx`.

**No italics anywhere.** Not consistent with Fletcher's terse-direct voice.

## Color

Palette locked from Phase 1 + Phase 2. Phase 3 introduces **zero new colors**; it only assigns semantic roles.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1A1A1A` | Screen background on every Phase 3 view |
| Secondary (30%) | `#242424` | Card surfaces — `SongOfDayCard`, technique-note cards, rating pill inactive background, tab container, chord scroll container, "From the bank" chip, `AlreadyRatedCard` |
| Accent (10%) | `#E07B39` (Fletcher orange) | See "Accent reserved for" list below — never a plain surface color |
| Destructive | `#c0392b` (existing) / `#3A1F1F` bg tint on error card | Breakdown error state ONLY. Never used on a rating pill (all three ratings are valid diagnostic input per fletcher-identity.md — no "bad" rating). |

**Supporting neutrals (already in use, formalized here):**

| Role | Value | Usage |
|------|-------|-------|
| Text primary | `#F5F5F5` | Song title, heading, primary body copy |
| Text muted | `#A0A0A0` | Fletcher intro-card body copy; retained for Fletcher line above song |
| Text secondary | `#999` | Artist name, tab string labels, meta line, section eyebrows |
| Text tertiary | `#666` | Meta line ("Blues · 84 BPM · Key of E") — retained from Phase 1 |
| Border neutral | `#333` | `SongOfDayCard` bottom divider between header and CTA row |
| Dot inactive | `#3A3A3A` | Progress dots inactive (from `FletcherIntroCard`) — unused in Phase 3 but reserved if any wizard-like flow appears |
| Disabled surface | `#4A3A2A` | Disabled CTA background (spent re-roll button, disabled primary CTA) — retained from `FletcherIntroCard` |

**Accent reserved for (exhaustive — never anywhere else):**

1. Primary CTA button background: "See the breakdown" on `SongOfDayCard`.
2. Selected rating pill: 3px left border + text color shifts to `#F5F5F5` on active (background stays `#242424`; the orange left border is the affordance, not a fill).
3. Chord diagram finger dots (`#E07B39`) — existing `ChordDiagram.tsx` convention.
4. Technique-note left border (3px) — existing `index.tsx` convention.
5. "From the bank" chip left border (3px) — matches technique-note pattern.
6. Difficulty badge border + text — existing `index.tsx` convention.
7. Eyebrow "TODAY'S SONG" text color — existing `index.tsx` convention.
8. Loader spinner tint (`ActivityIndicator color`) — existing convention.
9. Focus / pressed state on any interactive element: `opacity: 0.8` (existing `ctaPressed` convention). No orange glow, no shadow shift.

**Explicit prohibitions:**

- Do NOT use `#E07B39` as a filled background on the rating pills (would visually equate to "confirmed rating submitted" — the pill is *pre-tap* affordance, not a badge). The 3px left border is enough per `RetentionFormatRadio` precedent.
- Do NOT introduce a green "success" color. Post-rating acknowledgement uses the existing `#F5F5F5` heading + `#E07B39` accent line — the *copy* carries the win, not a color.
- Do NOT introduce a yellow/orange for "warning" on the re-roll counter. Disabled state is `#4A3A2A` background + `#999` text; that's the entire visual language for "you already used this."

## Copywriting Contract

**Voice source of truth:** `.planning/design/fletcher-identity.md`. Every string below has been vetted against the diagnosis → next step → confidence signal pattern. No emojis. No exclamation points. Second person, present tense.

### 1. Today tab — `SongOfDayCard` (baseline state)

| Element | Copy |
|---------|------|
| Eyebrow | `TODAY'S SONG` (unchanged from Phase 1) |
| Fletcher line (above song title, muted) | Dynamic based on selector path — see three variants below |
| Song title | `{song.title}` (dynamic, from API) |
| Song artist | `{song.artist}` (dynamic, from API) |
| Meta | `{genre} · {bpm} BPM · Key of {key}` (unchanged from Phase 1) |
| Skill tag chip (new) | `{primary_skill_name}` — e.g., "Blues Shuffle Rhythm", "E-shape barre chords". Sonnet-provided or read from the selector's target leaf skill. |
| Difficulty badge | `{difficulty}` (unchanged from Phase 1 — Beginner/Intermediate/Advanced text) |
| Primary CTA button | `See the breakdown` |
| Re-roll ghost button (fresh, 1 remaining) | `Not this one? Give me another. (1 left today)` |
| Re-roll ghost button (spent, 0 remaining, disabled) | `Not this one? Give me another. (0 left today)` |

**Fletcher line variants (choose based on selector path — API/planner determines which one):**

| Selector path | Fletcher line |
|--------------|---------------|
| 75% deterministic pick (argmin over `working_on`) | `You're leaning on this one. Play it today.` |
| 25% override — bank pick from user's own songs (any category) | `Something different today. Loosen up.` |
| 25% override / empty-working_on — bank pick from seed catalog | (no Fletcher line; the "From the bank" chip carries the signal instead — see below) |

The Fletcher line is optional and only renders when the selector path yields one of the first two variants. When the seed-catalog path fires, the chip alone communicates why (avoids over-explaining what is essentially a discovery moment).

### 2. Bank chip ("From the bank" micro-signal)

Small chip beneath the difficulty badge (or above the song title, planner's layout call — see Interaction Contracts §4).

| Selector path | Chip copy |
|--------------|-----------|
| 25% override — user's own songs bank | `From your bench` |
| 25% override / empty-working_on — seed catalog | `From the bank` |

Rationale: "your bench" (guitarist metaphor — the pile of songs you know but aren't currently drilling) reads warmer than "own songs bank." "The bank" (unqualified) signals seed-catalog when the user has literally no personal songs to draw from. Both phrasings are Fletcher-voiced: terse, musician-vernacular, no punctuation drama.

### 3. Breakdown loader (Fletcher voice, 3-phase rotation)

Reuses `uiStore.loaderMessageIndex` slice. Same timing thresholds as Phase 2's `preferences.tsx`.

| Time window | Copy |
|-------------|------|
| 0–3s | `Fletcher is listening...` |
| 3–8s | `Working out the fingering...` |
| 8s+ | `Almost there...` |

**Decision on 20s+ scenario (RESEARCH.md flagged Sonnet p90 at 20-30s):** we ship the three messages as-is. The third message ("Almost there...") is a coaching *promise*, not a countdown — it sustains regardless of remaining latency. Adding a fourth message ("Really this time...") reads sarcastic and undermines Fletcher's authority. If p90 pain becomes real in user testing, revisit as a Phase 4 concern.

### 4. Breakdown detail view

The breakdown detail view retains **exactly** the Phase 1 section eyebrows — no changes:

| Section eyebrow | Copy |
|-----------------|------|
| Technique notes section | `HOW TO PLAY IT` (unchanged) |
| Tab notation section | `TAB` (unchanged) |
| Chord diagrams section | `CHORDS` (unchanged) |

Each technique note keeps its `heading` (bold 15pt) + `body` (14pt, `#AAA` line-height 21) from Phase 1's exact styling. Content is Sonnet-generated per the `run_technique_breakdown` prompt in RESEARCH.md.

### 5. Rating pills (3-tier — the daily-loop climax)

Three horizontal pills, side by side, below the breakdown. Copy is locked per D-06 and fletcher-identity.md's "honest problems as self-report" pattern:

| Pill | Copy | Mastery shift |
|------|------|---------------|
| Left | `Not my tempo` | -0.05 (per D-08) |
| Center | `Getting closer` | +0.05 |
| Right | `That's what I'm looking for` | +0.15 |

**Do NOT alter these strings.** They are Fletcher's signature vocabulary (see fletcher-identity.md "Session rating buttons" section). "Not my tempo" is the film reference used *as coaching input* — the user is the one saying it, without shame. "Getting closer" is honest partial-credit. "That's what I'm looking for" is Fletcher's highest earned praise, delivered in his own voice back at him as the user's self-report.

### 6. Post-rating acknowledgement (Fletcher voice, per rating)

After a rating tap, the pill row + breakdown are replaced with a full-card acknowledgement. Copy templates from fletcher-identity.md's "Session summary micro-copy" section:

| Rating | Fletcher acknowledgement |
|--------|--------------------------|
| `Not my tempo` | `Slow the whole thing 10 bpm and rebuild tomorrow. You'll be back.` |
| `Getting closer` | `Getting closer. Same routine tomorrow — the next pass gets cleaner.` |
| `That's what I'm looking for` | `That's the tempo. Push it 5 bpm next session.` |

Below the acknowledgement, one secondary line: `See you tomorrow.` (14px `#999`, no CTA — the day is done).

After 2 seconds, the card auto-navigates back to the Today tab in the "already rated" state (see §8). The user can also tap anywhere on the acknowledgement card to dismiss it early — same 2s timer pattern established in Phase 2's fail-open card.

### 7. Breakdown error state (Sonnet failed after retry)

Full-screen card (uses `BreakdownErrorCard`, dark red-tinted background `#3A1F1F` for card surface — the only red on the entire screen).

| Element | Copy |
|---------|------|
| Heading (20pt bold, `#F5F5F5`) | `Fletcher lost the thread.` |
| Body (16pt regular, `#A0A0A0`) | `The connection dropped mid-thought. Give it a minute — try again.` |
| Primary CTA button | `Try again` |
| Secondary link (14pt, `#999`, tappable) | `Back to today's song` |

Voice notes:
- "Fletcher lost the thread" is diagnosis-shaped without blaming the user or the app. Anthropomorphic — Fletcher forgot, not "the request timed out."
- "Give it a minute" is the coaching next-step (not "please wait" — that's help-desk voice).
- `Back to today's song` returns the user to the `SongOfDayCard` state, breakdown ungenerated. Same-day retry limit is the server's problem (breakdown call rate limit is Phase 4; Phase 3 allows unlimited retries client-side because a failed call didn't produce a cached breakdown row).

### 8. Post-rating same-day return state (Today card, rated)

When the user returns to Today after rating (either via nav or after the 2s auto-navigate), the `SongOfDayCard` shows a variant with no primary CTA and no re-roll.

| Element | Copy |
|---------|------|
| Eyebrow | `TODAY'S SONG` (unchanged) |
| Fletcher line | `You already rated this today. See you tomorrow.` |
| Song title + artist + meta + skill tag + difficulty badge | All rendered as usual |
| Primary CTA area | Replaced with a static row: `Rated: {rating_label}` at 14px `#E07B39` — one line, no button |
| Re-roll ghost button | Not rendered at all (spent + rated = no interaction affordance) |

The song content stays visible — the user can still tap the song title area to re-open the breakdown detail view read-only (rating pills replaced with the same "Rated: {rating_label}" line). This lets the user reference the tab and chords for the rest of the day.

### 9. Empty-graph fallback (extreme edge case — bank empty AND working_on empty)

Full-screen `FletcherIntroCard`-style card. Only fires if the user has zero songs across all categories AND the seed catalog somehow returned nothing (should never happen in practice — seed catalog ships with 10 hand-curated songs per RESEARCH.md).

| Element | Copy |
|---------|------|
| Heading (24pt bold, `#F5F5F5`) | `Nothing to hand you today.` |
| Body (16pt regular, `#A0A0A0`) | `Add some songs from Settings and Fletcher will pick up tomorrow.` |
| Primary CTA button | `Open Settings` (navigates to Settings tab where the "Re-run onboarding" action lives) |

Voice notes: "Nothing to hand you today" carries the loss without drama. "Fletcher will pick up tomorrow" is the confidence signal — the app isn't broken, the day is just barren. This is the ONE Phase 3 string that includes a period after a two-word noun phrase without a verb (short, intentional; matches Fletcher's terse-diagnosis rhythm).

### 10. Re-roll interaction copy

Handled by the button state above (§1). One additional piece of micro-copy for the moment the user taps re-roll and the new song loads:

| Element | Copy |
|---------|------|
| Fletcher line above the newly-rolled song (temporary, first render only) | `Different song. Same work.` |

This line persists for the rest of the day on the new `SongOfDayCard` (replaces whichever of the three variant Fletcher lines from §1 would otherwise appear). The re-roll produced by the user is always a "bank" path (the deterministic argmin is skipped by definition when the user asks for something else), so the appropriate `From your bench` / `From the bank` chip also shows.

## Interaction Contracts

The 6-dimension checker validates interaction rules separately from the visual dimensions above. Locking them here per phase constraint.

### 1. Tap targets

| Element | Minimum touchable area |
|---------|-------------------------|
| Primary CTA "See the breakdown" | Full-width button, 48px tall (2xl token). Full width minus 32px horizontal padding. |
| Rating pills (3 of them) | Each pill 48px tall (2xl token), equal thirds of the row width minus 16px inter-pill gap × 2. Text label centered. |
| Re-roll ghost button | Visual height 32px, `hitSlop={{top:8, bottom:8, left:8, right:8}}` to reach 48px effective touchable. |
| Try again / retry buttons | Same 48px height as primary CTA. |
| Song title (tap to re-open breakdown from rated state) | Full song header row, minimum 44px vertical touchable via padding. |

All tap targets meet or exceed Apple HIG 44×44 and Google Material 48×48 minimums.

### 2. Loading states

Every network operation shows an immediate visual acknowledgement — no dead-tap moments.

| Trigger | State |
|---------|-------|
| Tap "See the breakdown" | Screen replaces with `FletcherLoader` full-screen (spinner + rotating message). Zero delay. |
| Tap re-roll ghost button | Ghost button disables + shows small `ActivityIndicator` inline where the counter used to be. `SongOfDayCard` fades to 0.5 opacity during fetch. |
| Tap rating pill | Pill immediately shows its "confirmed" visual state (3px `#E07B39` left border + slight scale to 1.02 for 150ms then back to 1.0). Other two pills disable. Then the post-rating acknowledgement card slides in from bottom (200ms translateY + opacity fade). |
| Tap "Try again" on error card | Card shows inline spinner replacing the button text; button disabled. Same behavior as breakdown loader. |

Loading text (Phase 1's plain `Loading...` on Today tab) is REPLACED across Phase 3 by the `FletcherLoader` for consistency. Phase 1's `<ActivityIndicator size="large" color="#E07B39" />` primitive is reused inside `FletcherLoader`.

### 3. Disabled states

| Element | Disabled visual |
|---------|-----------------|
| Primary CTA (during any mutation in flight) | Background shifts to `#4A3A2A`, text `#fff` unchanged, `opacity: 1.0` (not the pressed 0.8 — because disabled ≠ pressed), no tap response. |
| Re-roll ghost button after use | Text becomes `#666` (tertiary), background stays transparent, no border change, no press animation. Reads as "spent" not "broken." Counter text updates to `(0 left today)`. |
| Rating pills after one has been tapped (during the 2s post-rating transition) | All three pills opacity 0.5, no press response. Only the tapped one retains its confirmed visual. |
| Rating pills in "already rated today" state | Not rendered at all — replaced by the single-line `Rated: {rating_label}` static text. |

### 4. Bank chip placement

The `FromTheBankTag` chip appears **beneath the difficulty badge**, top-left of the `SongOfDayCard`, on its own row with a 4px vertical gap from the badge. Rationale: the difficulty badge is already an orange-bordered chip in the same location per Phase 1 code; keeping the bank chip in the same neighborhood makes it visually one "metadata cluster" without inventing a new region on the card.

Chip visual:
- Background `#242424`, 3px left border `#E07B39`, 6px horizontal + 4px vertical padding.
- Label 14pt semibold `#F5F5F5`.
- No icon (all-text; matches Fletcher's "terse-direct" voice — the chip is a label, not a badge that needs a symbol).

The chip does NOT appear when the deterministic 75% path fired. That's the default expected path; over-explaining it would be noise.

### 5. Rating pill layout

Three pills laid out horizontally with 12px gap between them. Full-row width matching the breakdown content column width (screen width minus 32px horizontal padding).

- Inactive (all three, default): `#242424` background, no border, 14pt semibold `#F5F5F5` label, centered text.
- Pressed (finger down): opacity 0.85.
- Confirmed (post-tap, briefly during the 200ms transition): 3px `#E07B39` left border, unchanged background, unchanged text color.

**No pill grouping affordance.** Do NOT wrap the three pills in a bordered container — they read as three separate cards, mirroring `RetentionFormatRadio`'s vertical stack semantic (which uses no group border either). This is a deliberate choice: they're independent tap targets, not options in a form.

Alignment note: pills sit BELOW the breakdown, above the safe-area bottom inset, with 24px (lg) top gap from the last chord diagram row and 24px (lg) bottom gap before the safe area. Never scrolled off-screen while a breakdown is loaded — they are the terminal action.

### 6. Gestures

No gestures beyond taps. Per D-09 (no pull-to-refresh on Today tab), the following gestures are **explicitly forbidden**:

- Pull-to-refresh on the Today tab or breakdown detail view.
- Swipe-to-dismiss on the breakdown detail (user must tap "Back to today's song" or the header back arrow — the breakdown is not a modal, it's a routed screen).
- Long-press on any rating pill (would suggest an "undo" affordance that doesn't exist per D-08).
- Horizontal swipe between pills (they're tap-only, not a segmented slider).

### 7. Horizontal scroll (multi-measure tab + chord row)

Per RESEARCH.md §2, the extended `TabNotation` accepts N measures and wraps them in a horizontal `ScrollView`. Contract:

- Show 2 measures on-screen at typical iPhone widths (14-Pro = ~390pt content width; each measure is ~192pt including left margin + 4 beats × 48pt beat width). Any additional measures scroll horizontally.
- `showsHorizontalScrollIndicator={true}` on tab (unlike chords, where it's hidden per existing code) — because the tab is content-dense, not visually decorative like a chord grid row. Users need to know they can scroll.
- Sonnet system prompt (per RESEARCH.md) caps measures at 8. Client renders whatever it receives; no client-side truncation.
- Each measure is `React.memo`'d per RESEARCH.md §2's memoization requirement.

Chord diagram scroll (existing pattern from Phase 1): horizontal `ScrollView` with `showsHorizontalScrollIndicator={false}`. Chord count is unbounded but expected 3-6 typically; 8px right-margin per diagram (existing `ChordDiagram.styles.wrapper.marginRight: 8`).

### 8. Transitions

| From → To | Transition |
|-----------|------------|
| `SongOfDayCard` → Breakdown loader | Immediate replace (no animation) — feels responsive; users don't want to wait through a fade before the wait for Sonnet |
| Breakdown loader → Breakdown detail | Cross-fade 200ms (masks the moment Sonnet returns) |
| Breakdown detail → Post-rating card | Slide-up 200ms (translateY from 40 to 0) + opacity fade (0 to 1). Emphasizes the completion moment |
| Post-rating card → Today (rated state) | 2s auto-navigate OR tap-anywhere-to-dismiss. Cross-fade 200ms |
| Any state → Breakdown error card | Cross-fade 200ms |
| Error card → retry (loader) → success | Standard cross-fades |

No spring animations. No hero animations across screens. All transitions are simple `Animated.timing` with `duration: 200, useNativeDriver: true`. Follows Phase 2's precedent (`preferences.tsx` uses no animations beyond the setTimeout loader rotation).

### 9. Timezone header

`X-Timezone-Offset` header is injected in `apiClient.ts` on every request (per RESEARCH.md §6). No UI surface for this — user never sees it. Included here so the checker knows the interaction contract for the daily-rotation trigger (D-09/D-10) is a header, not a user-facing time picker.

### 10. Idempotency signals

If a rating POST returns 409 (already rated this song today), the client silently transitions to the "already rated" post-rating state — user sees no error. The 409 is a "you already did this" not a "something broke," and the UI treats it as a state-sync moment. This is the ONE HTTP error code that Phase 3 UI does not surface as an error card.

If the re-roll POST returns 409 (already re-rolled today), the client refreshes the today-song query and shows the current song's `SongOfDayCard` in its "spent re-roll" state. No error surface. Same rationale.
